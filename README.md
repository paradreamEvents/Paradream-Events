## Rebuilding

Pages share a header and footer generated by `build.py`. Edit `build.py`, then:

```
python3 build.py
```

Editing the `.html` files directly is fine too — just remember `build.py` will
overwrite them if you run it again.

## What's new in this version

**Hero slider** — three rotating slides, auto-advance every 6.5s, pauses on hover,
dots to jump. Swap the images in `build.py` under `home = f"""`.

**Scroll animations** — anything with `class="reveal"` fades up as it enters view.
Add the class to any element. `reveal-d1`/`d2`/`d3` stagger it.

**Counters** — the four numbers on the home page count up once. Change them with
`data-count` and `data-suffix`.

**Gallery lightbox** — click any gallery photo to open it full-screen. Arrow keys
and Escape work.

**Quote calculator** (Contact page) — visitors pick occasion, guest count and
services, and get an estimated range. "Send this to Paradream" carries the
summary into the contact form.

> **Set your real prices.** Open `main.js` and edit the `PRICING` object at the
> top. The numbers in there now are placeholders I made up — replace every one
> before this goes live, or you'll be quoting figures you never agreed to.

**WhatsApp button** — bottom right, opens a chat to +961 81 406 046.

**AI assistant** — the red bubble. Two modes:

1. *Without an API key* — answers from a built-in list covering pricing, booking
   lead time, services, catering, location, contact and occasions. Works today,
   no setup.
2. *With an API key* — real conversation, powered by Claude, in whatever language
   the visitor writes.

To turn on mode 2:

1. Get a key at console.anthropic.com (this is paid per use, separate from any
   Claude subscription)
2. In Netlify: Project configuration -> Environment variables -> add
   `ANTHROPIC_API_KEY`
3. Redeploy

The key lives on Netlify's servers, never in your public code. If the key is
missing or the API is down, the widget silently falls back to mode 1.

Edit what the assistant knows in `netlify/functions/assistant.mjs` — the `SYSTEM`
text at the top.

## Testing forms and images (must be on Netlify — not the local demo)

Netlify Forms only works after Netlify scans your **deployed** HTML, and
`/.netlify/images` is an endpoint on Netlify's servers. Neither works from a
file on your desktop.

### 1. Deploy

```
git add .
git commit -m "image cdn, thank-you page"
git push
```

### 2. Turn on form detection

Netlify -> Forms -> **Enable form detection**, then redeploy (or push again).
Until this is on, submissions go nowhere.

### 3. Add email notifications

Project configuration -> Notifications -> Emails and webhooks ->
Form submission notifications -> Add notification -> Email notification.

Do it twice: once for `event-enquiry`, once for `join-us`.

Because the contact form has a field named `email`, the notification's Reply-to
is set to the customer, so you can reply straight from your inbox.

### 4. Test

Visit the live site, submit the contact form. You should:
- land on `/thanks.html`
- see the submission under the Forms tab
- get an email

If nothing arrives: check the Forms tab first. Submission there but no email
means the notification isn't set up. Nothing there at all means form detection
is still off, or the site hasn't redeployed since you enabled it.

### 5. Images

Photos in the gallery and services now load through Netlify Image CDN:

```
/.netlify/images?url=/images/gallery-1.jpg&w=700&fit=cover&q=80
```

Each `<img>` carries a `srcset` so phones download small files and large
screens get sharp ones. The lightbox pulls a 1600px version.

**What this means for you:** export photos ONCE at high resolution (about 2000px
on the long edge) into `images/`. Don't make thumbnails — the CDN does that.

Quality knobs, if you want to change them, live in `build.py` in the `cdn()`
helper: `q` is 1-100 (default 75, we use 80), and `fm=webp` can be added to
force a format, though Netlify already picks the best one per browser.

**Source quality matters most.** A photo that has been through WhatsApp is
already compressed and cannot be recovered. Get originals from the photographer,
or send them through WhatsApp as *Document* rather than *Photo*.

## Christmas countdown + spin wheel (`spin.js`, `spin.css`, `netlify/functions/spin.mjs`)

A navy countdown bar above the header ("Christmas is coming! 83d 07h ... Book Your
Christmas Event") and a "Spin for a Christmas Surprise!" popup. It is seasonal: it
only shows between `start` and `end` (1 Oct - 26 Dec 2026).

**One spin per email address.** The visitor enters their email; the Netlify function
`spin.mjs` gives that address one spin, ever, picks the prize on the server (so the
odds cannot be changed in the browser) and makes the claim code. Case, `+tags` and
Gmail dots are ignored, so `Jo.E+1@gmail.com` and `joe@googlemail.com` are the same
person. A second try with the same email is refused without revealing the first
prize. The email is not verified - anyone can type someone else's address, and
someone with many addresses can spin many times.

- **Prizes and odds** - the `PRIZES` table at the top of `netlify/functions/spin.mjs`
  (whole-number weights; they add up to 100 now):
  Try Again 30, Free consultation 10, 10% off 10, 20% off 5, Try Again 30,
  Free candy 10, Free Santa character 5. "Try Again" is **no prize** (60% in total).
  The wheel's order and the prize wording live in `CONFIG.prizes` in `spin.js`; the
  `id`s must match (a check fails loudly if they drift).
- **Where entries go** - Netlify Blobs (store `spin-entries`, one record per email:
  email, prize, code, time) and the Netlify form **`spin-entry`**. Add an email
  notification for `spin-entry` in Netlify (Forms -> Form notifications) like the
  other forms; the entries then also appear under Forms and can be exported as CSV.
- **Claiming** - the winner sees a code like `PD-7K3QX`, a "Claim on WhatsApp" button
  (message pre-written with the code) and a link to the Christmas page, where the
  prize and code are pre-filled into "Special Instructions". Codes are random labels
  that arrive with the enquiry; match them against the `spin-entry` list.
- **How it behaves** - opens by itself after 9 s or at 45% scroll, once per visitor
  (snoozed 3 days if closed; never again after they spin). Never auto-opens on pages
  with a form. A small "Spin & win" pill (bottom-left) reopens it.
- **Preview locally** - `npm install` once, then `node dev-server.mjs` and open
  `http://127.0.0.1:8123/index.html?spin=1`. This runs the real function with a local
  Blobs store (kept in `.netlify/blobs-local`), and shows the photos. `--fresh` forgets
  every email that has spun; `--lan` also serves your phone on the same Wi-Fi.
  `?spin=1` ignores dates; `?spin=reset` also forgets the result saved in your browser.
- **Deploying it** adds `package.json` (one dependency, `@netlify/blobs`), so Netlify
  runs `npm install` during the build, and one function. Nothing else to configure.
- **Retire it** - delete the `spin.css` and `spin.js` lines in `build.py` (search
  `spin.`), delete the `spin-entry` form block at the end of the thanks page in
  `build.py`, and rebuild.
